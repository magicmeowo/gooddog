## 1. 目标与非目标

### 产品目标
让想养狗、但没想清楚的人，通过一套有趣的测试，**5 分钟内**得到一个真正适合自己生活方式的养狗建议，降低"养错"的焦虑。

### 衡量是否成功（北极星 & 信号）
- 主信号：**测完愿意转发 / 截图分享**（说明又准又好玩）
- 辅助：完成率（开始测的人有多少测到结果）、结果页停留时长（愿不愿意读"为什么是它"）

### 非目标（MVP 明确不做）
- ❌ 不做交易撮合（不对接宠物店 / 领养机构）
- ❌ 不做养狗后的养护工具（喂养记录、提醒等）
- ❌ 不做账号体系、登录、收藏（结果用链接 / 截图分享即可）
- ❌ 不做个体狗狗匹配（只到"品种"粒度）

## 2. 用户与场景

| | 主要用户 | 次要用户 |
|---|---|---|
| 是谁 | 想养狗、没养过 / 没想清楚的小白 | 在 2–3 个品种间纠结的准买家 |
| 心态 | 又想养又怕养错、信息过载 | 已有倾向，要临门一脚 |
| 我们给什么 | 科普 + 安抚 + 一个清晰建议 | 验证 / 推翻他的倾向 |

**典型场景**：晚上刷手机，刷到朋友转发的「测测你适合养什么狗」，点进去，躺着花 5 分钟答完，得到结果 + 一个好玩的「养宠人格」标签，截图发朋友圈 / 群里。

---

## 3. 用户流程

```
落地页（讲清楚这是什么 + 一句钩子）
   ↓ 点「开始测试」
答题（8–10 题，单选为主，一题一屏，带进度）
   ↓ 自动进入
计算中（1–2 秒，动效缓冲，制造期待）
   ↓
结果页
   ├─ 你的「养宠人格」四字标签 + 一句话画像
   ├─ 最佳匹配狗狗（1 只）+ 为什么是它（按维度解释）
   ├─ 备选 Top 2~3
   ├─ 给你的一句现实提醒（按动机定制口吻）
   └─ 分享 / 重测
```

🔶 **决策点**：
- 形态 = **H5 网页**（最轻、好传播、免审核、跨平台）
- 结果 = **Top 3，置顶 1 只最佳**（一只太武断，三只给选择不过载）
- 传播钩子 = **「养宠人格」四字标签**（MBTI 式，增强转发）

## 4. 题库结构

### 设计铁律（来自 00-idea）
> 每道有趣的题，背后都挂一个真实筛选维度。题目越像在聊"你是个什么样的人"、越不像填表，越成功。

### 一道题的数据结构
```jsonc
{
  "id": "q_morning",
  "text": "理想的周末早晨是——",
  "options": [
    { "label": "😴 睡到自然醒，不想动",        "scores": { "exercise": 1 } },
    { "label": "☕️ 慢慢起，遛个弯喝杯咖啡",      "scores": { "exercise": 3 } },
    { "label": "🌅 六点起来跑步 / 爬山",         "scores": { "exercise": 5 } }
  ],
  "maps_to": "exercise"   // 这道题在偷偷测哪个维度
}
```
- 大多数题是「软题」→ 给某个**负担维度**打 1–5 分。
- 少数题是「硬题」→ 触发**门槛过滤**（如居住空间、过敏、是否合租），答案直接圈定 / 排除一批狗。
- 1–2 道「喜好题」→ 只影响排序微调（外形 / 性格偏好）。

### 题量与配比（🔶 草案）
共 **9 题**，约 3–5 分钟：
| 类型 | 题数 | 覆盖 |
|---|---|---|
| 硬门槛题 | 3 | 居住空间&体型、吵闹环境、同住人/过敏 |
| 负担软题 | 4~5 | 运动量、打理、独处耐受、训练经验、预算 |
| 喜好题 | 1~2 | 外形 / 性格偏好 |

> 注：一道题可同时给多个维度打分（提高效率、减少题数）。

## 5. 狗狗数据模型

每个品种用**与用户侧同一套维度**打分，两边才能比。

```jsonc
{
  "id": "corgi",
  "name": "柯基",
  "name_en": "Welsh Corgi",
  "photo": "/data/mock/dogs/corgi.jpg",
  "size": "small",            // 门槛：small / medium / large
  "traits": {                 // 负担维度，1=低/易，5=高/难
    "exercise": 3,            // 运动量需求
    "grooming": 4,            // 打理投入（掉毛多）
    "alone_tolerance": 3,     // 独处耐受（越高越能独处）
    "trainability": 4,        // 训练难度（注意方向，见下）
    "budget": 3              // 月开销
  },
  "filters": {                // 门槛标签
    "noise": 3,              // 吠叫程度 1–5
    "hypoallergenic": false, // 是否低敏/少毛
    "good_with_kids": true,
    "novice_friendly": true
  },
  "personality": ["黏人", "活泼", "固执"],  // 喜好题匹配 & 文案
  "one_liner": "短腿小推土机，热情话痨，掉毛像下雪。",
  "real_talk": "聪明但固执，掉毛是真的多，爱叫，要早训练。"
}
```

🔶 **MVP 覆盖热门 25 种**（柯基、金毛、拉布拉多、泰迪/贵宾、柴犬、边牧、哈士奇、萨摩耶、比熊、博美、雪纳瑞、法斗、巴哥、腊肠、柯基、中华田园犬、阿拉斯加、德牧、柴犬、约克夏、马尔济斯、可卡、柯利、蝴蝶犬、吉娃娃……以最终清单为准）。数据先人工标注放 `data/mock/dogs.json`。

## 6. 匹配算法（可解释优先）

分三步走，对应三层维度。**核心要求：结果能用人话解释"为什么是它"**，不能是黑箱。

### Step 1 · 门槛过滤（硬约束，先做减法）
根据硬题答案，**排除**明显不合适的狗：
- 住小公寓 / 小区限大型犬 → 排除 `size: large`
- 合租 / 怕吵 → 排除 `noise ≥ 4`
- 有人过敏 → 只保留 `hypoallergenic: true`
- 家里有小孩 → 只保留 `good_with_kids: true`
- 纯新手 → 给 `novice_friendly: false` 的狗大幅减分（不一定全排除）

> 过滤后剩下「候选池」。

### Step 2 · 负担打分（核心，加权匹配）
对候选池每只狗，比较「**狗的要求** vs **用户能提供的**」，算匹配分。

**关键设计 —— 不对称惩罚**：
> 痛苦主要来自「**狗要求的 > 用户能给的**」（狗要每天跑步、主人只想躺平 = 灾难）。
> 反过来「用户能给的 > 狗要求的」（主人精力旺盛、狗很佛系）基本不痛苦，只轻微扣分。

伪逻辑：
```
对每个负担维度 d：
  gap = dog.traits[d] - user.capacity[d]
  if gap > 0:  penalty = gap * 权重[d]        # 狗要求超出用户，重罚
  else:        penalty = |gap| * 权重[d] * 0.2 # 用户富余，轻罚
匹配分 = 100 - Σ penalty（归一化）
```
权重 🔶（草案，运动量和独处最致命）：
`exercise 1.5 · alone_tolerance 1.3 · grooming 1.0 · trainability 1.0 · budget 1.0`

### Step 3 · 喜好排序（微调）
负担分相近时，用喜好题（外形 / 性格偏好）打破平手、决定 Top3 顺序。

### 输出
- 最佳匹配 1 只 + Top 2~3 备选
- 每只附「为什么是它」：列出 2–3 条命中的维度（"你想躺平，它也不爱动 ✓"）和 1 条要注意的（"但它掉毛多，得接受"）

## 7. 结果呈现

1. **养宠人格标签**：把用户的维度画像映射成一个四字称号 + 一句话画像（🔶 例：低运动+高陪伴+怕麻烦 = 「居家暖被窝型」）。这是传播钩子。
2. **最佳匹配狗**：大图 + 名字 + 一句话 + 为什么是它（按维度解释）+ real_talk 现实提醒。
3. **备选 Top 2~3**：小卡片。
4. **动机定制口吻**（来自 WHY）：审美型 → 强调现实成本提醒；陪伴型 → 强调情感共鸣。
   > MVP 简化：可先不专门测动机，用统一温暖口吻 + 必有的 real_talk 提醒。🔶
5. **分享**：生成结果卡片图（可截图），含标签 + 狗狗。

## 8. MVP 范围（先做什么）

**做**：落地页 → 9 题 → 结果页（Top3 + 养宠人格标签 + 为什么 + 现实提醒）+ 截图分享。25 个品种。纯前端，数据写死在 mock。

**不做**：登录、后台、真实数据库、动机分支文案、生成分享图（可先用"截图保存"替代）、犬种详情页。
